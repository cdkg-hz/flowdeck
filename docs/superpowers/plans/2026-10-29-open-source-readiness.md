# Flowdeck 开源准备计划

**目标：** 让现有源码具备首次公开到 GitHub 的说明、许可、协作入口和可重复验证方式。

**范围：** 保留现有 Python / React / Compose 架构，补充仓库文件；不创建远程仓库、上传代码或发布制品。用户已选择 MIT。

**实现选择：** 采用完整基础开源配套；不引入新的业务功能、运行框架或付费服务。没有现存 Git 仓库，直接在当前源码目录补齐文件。

## 验证重点

1. README 的全新安装不依赖作者个人域名、真实密钥或生产数据。
2. CI 使用 pull_request 与只读权限，外部 PR 无需生产 Secrets。
3. 锁文件覆盖运行依赖，避免镜像可构建但应用导入失败。
4. 浏览器验收实际运行，不把默认跳过当成验收通过。
5. 尚未存在的 GitHub URL、维护者账号和邮箱不填造；仓库侧设置写入发布清单。

## 验证中发现的问题

- 首次完整测试：221 passed、1 failed、3 skipped。失败原因为 Actions Secrets 加密代码导入 `nacl`，但运行依赖和锁文件未声明 PyNaCl；仅安装锁文件的独立虚拟环境也复现了该问题。补齐声明与锁定版本，不修改加密逻辑。
- 浏览器验收：安卓签名文本同时匹配分组标题和文件字段；改为按 fieldset 的 group 角色与完整可访问名称定位，保留原验收内容。
- 继续执行浏览器验收时发现项目创建新增的 GitHub Webhook 注册调用未被隔离，使用虚假 PAT 访问 GitHub 后返回 422；沿用 API 测试的方式仅替换该外部注册操作，本地界面、API、数据库与签名 ping 仍真实运行。
- 本机无 Docker，镜像构建与 Compose 验证只能交由新增 CI 在 GitHub runner 执行；不声称已通过。
